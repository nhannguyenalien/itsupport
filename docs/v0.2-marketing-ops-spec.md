# AI Marketing Operations Agent — v0.2 scope contract

Captured verbatim from the user's planning message (2026-09-02), expanding the
original "Ads Copilot" into a Marketing Operations Pack. This is the source of
truth for what's in v0.2 — if it's not here, it's not in scope yet.

## Positioning

Not just "AI runs Facebook/Google Ads." Instead:

> AI Marketing Operations Agent — giám sát quảng cáo, tracking, website và
> conversion funnel; phát hiện lỗi, đề xuất tối ưu và thực thi có kiểm soát.

Agencies and businesses don't just suffer from "ads" — they suffer from broken
tracking, broken landing pages, lost leads in the CRM, and not knowing *where*
a KPI drop actually originates. The product's value is diagnosing across the
whole funnel (ads → tracking → landing page → CRM), not just an ads dashboard.

## Product packaging (3 packs)

```
CORE BROWSER               ADS PACK                  MARKETING OPS PACK
├── Browser Worker          ├── Google Ads             ├── GA4
├── AI                      ├── Meta Ads               ├── tracking
├── Policy                  ├── metrics                ├── landing page
├── Approval                ├── optimization            ├── CRM
└── Audit                   └── alerts                  ├── reporting
                                                          └── business KPIs
```

Sellable as two SKUs: **AI Ads Assistant** (freelancer/small agency, Ads Pack
only) and **AI Marketing Operations** (larger business, full stack).

## Execution model (explicit user direction, 2026-09-02)

- **API-first.** Every tool talks to the platform's real API using a token
  the *backend* obtained and stores per-tenant (OAuth), not something the
  end user pastes in each time and not something the AI types into a UI.
- **Computer Use (browser control) is the fallback only** — for whatever a
  platform genuinely has no API for (e.g. some CRM web consoles). Prefer API
  everywhere an API exists.

## Tool taxonomy (full — 12 groups, source list)

### 1. Ads tools (cross-platform, required)
`ads.accounts.list`, `ads.campaigns.list`, `ads.adsets.list`, `ads.ads.list`,
`ads.metrics.read`, `ads.metrics.compare(current_period, previous_period)`,
`ads.breakdown.read`, `ads.budget.update`, `ads.campaign.pause`,
`ads.campaign.enable`, `ads.schedule.read`, `ads.schedule.update`,
`ads.creative.read`, `ads.creative.status`, `ads.search_terms.read`,
`ads.keywords.read`, `ads.negative_keywords.read`, `ads.conversions.read`,
`ads.attribution.read`.

`ads.metrics.compare` exists specifically so the AI can answer "Vì sao CPA
tuần này tăng?" with real period-over-period data, not a guess.

### 2. Google Ads-specific
Read-only first: `google_ads.search_terms`, `google_ads.keyword_metrics`,
`google_ads.quality_score`, `google_ads.impression_share`,
`google_ads.auction_insights`, `google_ads.conversion_actions`,
`google_ads.disapprovals`, `google_ads.recommendations`,
`google_ads.pmax.assets`, `google_ads.pmax.asset_groups`.
Then write (approval-gated): `google_ads.keyword.add`,
`google_ads.negative_keyword.add`, `google_ads.bid.update`.

### 3. Meta Ads-specific
`meta_ads.campaigns`, `meta_ads.adsets`, `meta_ads.ads`,
`meta_ads.breakdowns`, `meta_ads.placements`, `meta_ads.frequency`,
`meta_ads.cpm`, `meta_ads.ctr`, `meta_ads.cpc`,
`meta_ads.creative.preview`, `meta_ads.creative.status`,
`meta_ads.pixel.status`, `meta_ads.events.read`, `meta_ads.attribution.read`.
`meta_ads.frequency` is called out as critical — creative-fatigue detection
(e.g. "Frequency 4.8, CTR giảm 37% trong 5 ngày → khả năng creative fatigue
cao").

### 4. Tracking / Conversion
`tracking.pixel.detect`, `tracking.google_tag.detect`, `tracking.gtm.detect`,
`tracking.event.test`, `tracking.event.list`, `tracking.utm.validate`,
`tracking.conversion.verify`, `tracking.pageview.test`,
`tracking.form_submit.test`, `tracking.purchase_test`.
Exists so "Facebook có click nhưng không thấy đơn" can actually be diagnosed
by walking Landing page → Pixel → event → conversion → CRM/order, not just
staring at Ads Manager.

### 5. GA4 / Analytics
`analytics.sessions`, `analytics.users`, `analytics.source_medium`,
`analytics.campaigns`, `analytics.conversions`, `analytics.landing_pages`,
`analytics.events`, `analytics.funnel`, `analytics.realtime`,
`analytics.compare_periods`. Lets the AI distinguish "ads có vấn đề" from
"ads ổn nhưng landing page conversion tụt."

### 6. Landing page / Website (Browser Worker / Computer Use territory)
`web.page_open`, `web.performance`, `web.console_errors`,
`web.network_errors`, `web.form_test`, `web.button_test`,
`web.checkout_test`, `web.mobile_view`, `web.link_check`, `web.ssl_check`,
`web.redirect_check`. Later: Lighthouse/PageSpeed API. Example value: ads
still running but leads drop — agent finds `/contact` form submit returns
HTTP 500 → website bug, not an ads problem.

### 7. CRM / Lead tools
Generic interface first: `crm.leads.list`, `crm.leads.count`,
`crm.leads.by_source`, `crm.leads.by_campaign`, `crm.pipeline.read`,
`crm.conversions.read`, `crm.lead.create`, `crm.lead.update`. v0.2: browser
support for web CRMs. Later: adapters for HubSpot, Salesforce, Zoho,
Pipedrive, custom CRM.

### 8. Business KPI layer (normalized, cross-platform)
`marketing.spend`, `marketing.leads`, `marketing.sales`,
`marketing.revenue`, `marketing.cpl`, `marketing.cac`, `marketing.roas`,
`marketing.mer`. This is what makes an answer like "Google Ads ROAS 4.2,
Meta 1.6 → chuyển 15tr từ Meta sang Google Search" possible — the
enterprise-value answer, not just raw CTR/CPC.

### 9. Reporting
`report.daily`, `report.weekly`, `report.monthly`, `report.client_summary`,
`report.anomalies`, `report.actions_taken`.

### 10. Alert engine
`alert.create_rule`, `alert.list`, `alert.disable`. Example rules: CPA >
300k → alert; spend > 120% daily budget → alert; ROAS < 1.5 for 3h → alert;
pixel stops receiving events → critical. Flow: **Alert → AI diagnose →
recommended action → approval**. Auto-remediation is explicitly a later
phase, not v0.2.

### 11. Creative support
Read/analysis first: `creative.list`, `creative.performance`,
`creative.compare`, `creative.fatigue_detect`, `creative.text_extract`,
`creative.image_analyze`, `creative.video_metadata`. Generation
(`creative.generate_copy`, `creative.generate_image`,
`creative.generate_variants`) is explicitly **not** v0.2.

### 12. Approval policy — must scale with money, not just risk tier
Marketing actions can directly cost money, unlike most IT actions. Needs:
`absolute_budget_limit`, `percentage_budget_limit`, `daily_spend_limit`,
`account_scope`. Example band (this is the actual policy to implement):

```
AI auto-executes:  decrease budget any amount, increase budget ≤10%, pause ad
Requires approval: increase budget 10–25%
Human only (not offered to the AI at all):
  increase budget >25%, payment, billing, add credit card, delete account
```

## Architecture reuse

Same proven shape as the Windows Support Agent (v0.1, `support-agent-platform`):
ticket-style investigation → AI proposes tool calls → policy engine decides
auto-execute / requires-approval / rejected → deterministic verification →
audit log. What's genuinely new for v0.2:

- **OAuth token custody**: backend obtains and stores per-tenant, per-platform
  access/refresh tokens (Google Ads, Meta, GA4, CRM). The AI/tools never see
  or handle credentials directly — they call an internal platform-client
  layer that injects the tenant's stored token.
- **Dynamic, money-aware risk**: unlike v0.1's static per-tool risk in
  `registry.json`, `ads.budget.update`'s risk depends on the *requested
  change* (% and absolute delta vs. current budget), computed at
  evaluation time against the tenant's configured limits.
- **Computer Use as an explicit fallback tier**, not a co-equal option —
  only reached when a tool's platform has no usable API for that action.

## Known gaps (do not fake)

- Real API access requires developer/app credentials this session doesn't
  have: a Google Ads **developer token** (requires applying to Google,
  approval can take days), a Meta **app with `ads_management` permission**
  (requires app review), and GA4 service-account/OAuth client credentials.
  Until provided, platform-client calls fail honestly (same pattern as
  v0.1's `OPENAI_API_KEY` handling) rather than returning fabricated data.
- No real CRM adapter exists yet beyond the generic interface shape.
- Creative generation, auto-remediation, and Computer Use itself are
  explicitly out of scope for this pass.
